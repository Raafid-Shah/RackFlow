**REFLECTIONS**

## Things that I was overconfident about and got wrong at start:
I assumed it would be easy to convince a medical shop to allow me to develop a tool with reference to their layout and suggest Improvements, but reality is different people are more cautious of having their time wasted in an endeavour they dont see immediate benefits of.

I believe the tool has reached a complexity that makes it a bit difficult to use by the pharmacy staff if they arent given a proper walkthrough, I could improve the intuitive nature of the application more, because it has a lot of features now, and would require for them to learn it. For what was supposed to be a simple experience, my development kind of complicated it a bit.


## Things that worked:
I managed to convince a pharmacy (Hope Pharmacy) with letting me take some data from their shelves, as to where the medicine is placed, how much time it took to find. metrics with regards to pricing, it was a tedious task but being thorough about it helped me with some last minute changes, like the MRP tally, which couldnt have been possible if I didnt take the prices into account beforehand.

Having a longer research time than suggested 1.5 hrs got me to really explore all the aspects that I had overlooked, inititally i had thought to make a minimalist tool for departmental stores, and found some tools used by walmart  but then I realised the scope of this within pharmacy's was much greater. 

I was able to serve the application via same wifi and allowing for offline functioning really makes this tool versatile in use. Allowing for use by multiple people in the pharmacy counter operators, helpers etc.

The Search feature is responsive and fast, few keywords get you the result that you are looking for, be it compound/salt or the name of the medicine, 

Upon creating a list of orders, the sorted nature based on distance is a great advantage. it makes it an easy walk in order, rather than moving back n forth through the shop finding medicines.


## Realisations

- Its always better to spend time in arranging information and creating a plan than to jump straight to execution, since that saved me quiet some time here, having a development plan ready, with all the tech stack, whether deployment was the way to move forward or have it served via wifi to all connected personnel with server running on a pc, typical of a pharmacy where a PC is always running for counters.

- Make your requirements clear to LLM's they are able to overdo in places where you want clear and concise responses and code. 

- Always get some readout about the feature the LLM's implement that helps build context of what was developed and what its utility is.
